# packages/ai-core

模型接入与 Prompt 工程的基础层，保证业务代码不绑定单一模型。

## 职责

- ModelProvider 抽象：OpenAI 兼容 API、DeepSeek 等实现的统一封装
- 模型配置：模型名、温度、最大 token、超时、重试策略
- Prompt 管理：模板目录、版本化、system/user/assistant 消息组装
- 结构化输出：JSON Schema / Zod 校验、解析失败的安全重试
- 工具抽象：工具注册、参数 Schema、调用协议
- 用量与成本：token 统计、耗时日志

## 规划结构（示意）

```text
ai-core/src/
├─ providers/    # 各模型供应商适配
├─ prompts/      # 客服、摘要、分类等模板
├─ schemas/      # Zod 校验与输出结构
├─ tools/        # 工具定义与注册表
└─ usage/        # 用量与成本统计
```

## 约定

- 密钥只能来自服务端环境变量，禁止写入代码或提交到仓库。
- 更换模型只改配置，不改业务层调用代码。
- 模型输出一律先校验再使用，校验失败必须显式处理。

## 开发任务清单

- [ ] Provider 抽象与统一消息格式，支持至少两个 OpenAI 兼容配置
- [ ] 模型配置管理：模型名、温度、最大 token、超时、重试、并发限制
- [ ] Prompt 模板：客服、摘要、分类三套，支持版本化与对比测试
- [ ] 结构化输出：JSON Schema / Zod 校验，不合格时安全重试一次
- [ ] 工具定义：`getCurrentTime`、`calculator`，含参数 Schema
- [ ] 上下文管理：最近 N 轮 + 超长历史摘要，Token 预算控制
- [ ] 可靠性：超时、重试退避、限流、统一错误码、幂等
- [ ] 用量统计：token 数、耗时、成本估算
- [ ] 测试：Mock 模型响应 + 20 条固定 Prompt 测试集

## 验收标准

- [ ] 切换模型只需改配置，业务代码零改动
- [ ] 密钥只从服务端环境变量读取，代码与日志中均不出现
- [ ] 模型输出非法时不崩溃：重试后仍失败则返回明确错误
- [ ] 上下文超限有裁剪策略，并有对应测试用例
- [ ] 20 条测试集可复跑，记录输出、耗时、失败率，支持两种 Prompt 对比
- [ ] 超时/失败返回统一错误码，调用方可区分可重试与不可重试
