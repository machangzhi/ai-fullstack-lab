# packages/agent

基于 LangGraph.js 的 Agent 编排层，用图结构管理多步推理与工具调用。

## 职责

- 工作流编排：State、Node、Edge、Conditional Edge、START/END
- 工具调用循环：最大迭代次数、失败分支、收尾节点
- 状态持久化：按 `thread_id` 保存 Checkpoint，支持中断恢复
- Human-in-the-loop：高风险工具的人工审批与恢复执行
- 记忆：会话内短期上下文、必要的长期记忆
- 可观测性：执行轨迹、每步输入输出、耗时与 token
- 可靠性：超时、重试、幂等、降级与评估用例

## 规划节点（示意）

```text
意图识别 → 工具选择 → 工具执行 → 结果校验 → 结果总结
                          ↘ 需审批 → 人工确认 ↗
```

## 约定

- 所有循环必须有最大步数，避免无限调用。
- 高风险工具（写操作、外部副作用）默认走审批，不自动执行。
- 执行轨迹需可落库，便于复盘与线上问题定位。

## 开发任务清单

- [ ] 手写简化 Agent Loop（记录每轮决策、工具入参与结果），作为对照实现
- [ ] ToolRegistry：注册、Zod 参数校验、执行超时、最大调用次数、错误隔离
- [ ] 只读业务工具：queryOrder、queryCustomer、calculateMetric（模拟数据）
- [ ] LangGraph 工作流：意图识别 → 工具执行 → 结果总结，含条件路由与循环终止
- [ ] Checkpoint：按 `thread_id` 持久化，支持中断后恢复
- [ ] HITL：高风险工具 `interrupt` 审批，未批准不执行并记录审计
- [ ] 记忆：会话摘要；仅保存明确允许的偏好，不无差别写入长期记忆
- [ ] 可靠性：工具超时/数据库失败的有限重试、失败节点恢复、人工接管
- [ ] 评估：30 条任务集，记录成功率、工具选择准确率、耗时、成本

## 验收标准

- [ ] 所有循环有最大迭代次数与超时，超限可安全结束并返回原因
- [ ] 工具参数校验失败时不执行工具，返回结构化错误
- [ ] 高风险工具未审批绝不执行，审计中包含操作者与参数
- [ ] 中断后可恢复执行，状态正确且会话相互隔离
- [ ] 执行轨迹可查：节点、输入、输出、耗时、错误
- [ ] 30 条任务评测有指标记录，并能定位失败类型
- [ ] 计划步骤经 Schema 与工具白名单校验后才执行
